# CCNU Radar 后端

初次运行、完整产品介绍和可复制示例，请先阅读 [项目根目录 README](../README.md)。根目录的 `npm start` 同时提供网页和 API；在本目录执行 `npm start` 只运行 API。下面保留后端实现细节与历史兼容说明。

## 首页与前端导航

- 首页默认展示最多 8 个近期已发布活动，按明确的活动开始日期排序；过往和取消活动不列入首页。未知日期排在后面，真实活动为空或服务失败时显示对应提示，不用演示数据冒充真实活动。
- 四个演示活动移入单独可展开区域，卡片和详情显示“演示”，不调用报名接口。本机未发布的解析记录显示“未发布”；“已发布”不代表已核验学校身份或通过学校审核。
- 前端根据现有接口明确标记 source=published/demo/local，兼容旧后端响应；此字段不参与身份或报名权限判断，不需要数据库迁移。
- 卡片和详情统一显示报名中、已满员、已截止、已取消；未知截止或名额标为待确认。每 30 秒更新时间，日期判断与后端使用相同的北京时间规则，报名最终仍由后端校验。
- 页面采用哈希地址（例如 #/search、#/parser、#/publications），支持刷新、前进和后退，切换页面回到顶部。旧 #events 链接仍能定位首页活动区；新首页锚点为 #/?section=events。无需新增服务器路由或部署路径重写。
- 长说明改为可展开详情；独立密码、学号未核验、收藏不等于报名、真实 AI 的数据发送与隐私提示仍保留。
- 本次无新增后端业务接口。本机开发页刷新即生效；分享版需重新运行 start-share.cmd 加载最新构建。presentation.test.js 验证来源、状态、日期、首页筛选和导航地址。

## 新注册账号教程

- 若教程完成时报“API endpoint not found”，通常是前端已更新但 3001/3002 后端进程仍在运行旧代码。重启对应服务后再保存，无需重新注册。界面会将此错误翻译为明确的中文版本提示。
- 教程保存失败时提供“暂时关闭，继续使用”，顶部关闭和 Esc 也可解除弹窗阻塞。此操作只在当前页面会话延后教程，不更改服务器完成状态；页面刷新后仍可重试，顶部“新手教程”可随时重开。

- 新账号注册后返回 onboardingCompleted=false，前端自动打开四步新手引导：搜索筛选、收藏与报名区别、AI 解析、发布管理和站内通知。
- 用户表新增 onboarding_completed，已有账号迁移时默认 1，不对老用户强制弹窗；新注册使用明确字段 INSERT 写入 0，保留原账号、密码和会话。
- 完成、跳过或按 Esc 关闭时，POST /api/auth/onboarding 保存当前会话账号的完成状态。接口要求登录并校验请求来源，不接受替他人修改状态。
- 教程完成状态随账号存于 SQLite，跨浏览器和服务重启保留。直接关闭网页而未完成/跳过的账号，下次登录仍会看到引导。
- 已登录用户可从顶部“新手教程”手动重看。最后一步完成后进入搜索页；跳过则停留在当前页面。
- 保存失败会显示错误并允许重试，不会假装已经完成。教程采用原生模态对话框，支持键盘、上一步/下一步、步骤跳转和手机宽度。
- onboarding.test.js 使用独立数据库验证新旧账号、迁移、持久化、会话权限和跨域限制。更新后重启本地后端与分享服务才会生效。

## 同步与限流修复

- 分享入口明确指定 tunnelProvider。默认不信任任何代理请求头；只有绑定本机回环的对应隧道入口启用代理识别。
- ngrok 仅取 X-Forwarded-For 最后一个合法地址，不读取 CF-Connecting-IP、不取客户端可伪造的前缀。依据：https://ngrok.com/docs/gateway/endpoints/http#upstream-headers 。Cloudflare 入口仅使用其对应请求头；地址缺失或无效时退回实际连接地址。不要将分享服务改为监听公网网卡，或在不受信任的代理后复用该配置。
- 注册/登录仍为每来源每 15 分钟 20 次；不同 ngrok 访问来源独立计数。同一校园出口/NAT 下的用户仍可能共享外网 IP，这是按 IP 限流的边界，不代表学校身份验证。
- POST /api/events/saved，JSON 为 {"ids":["活动编号"]}，每批最多 100 个，只返回所请求活动的公共信息、名额、取消状态和原因，不返回发布者或报名者身份。未知编号不作删除处理。
- “我的活动”进入页面和每 30 秒查询最新信息，并更新原 localStorage。保留保存顺序、未发布解析及已取消活动。网络异常时明确提示正在显示历史信息；存储失败时保留内存中的最新信息并提示。
- 活动卡片的本次报名缓存仅适用于当时的父级活动对象；新列表数据到达时旧缓存失效。详情打开时及每 30 秒、手动刷新名额时会同步更新卡片。
- npm test 增加 regressions.test.js，覆盖代理限流、防请求头绕过、活动同步、取消原因持久化、保留私有解析和名额缓存失效，均使用独立测试数据。

## 发布管理、名单和通知

- “我的发布”包含进行中及已取消/撤回活动。仅发布者能查看报名学号、北京时间报名时间，及导出带 UTF-8 BOM 的 CSV（可用 Excel 打开）。学号未经学校核验；导出文件请妥善保存。
- GET /api/events/:id/participants；同路径 ?format=csv 导出。均校验会话和发布者所有权，不返回密码、会话或内部账号 ID。
- PUT /api/events/:id：提交与发布相同的活动字段。保留活动 ID 和报名记录；不允许人数上限低于已报名人数；取消活动不能编辑。
- POST /api/events/:id/cancel：JSON 为 {"reason":"取消原因"}，必填 1–500 字。隐藏公共活动并停止报名，保留原始记录、原因和名单。报名同学可在“我的报名”和详情查看原因。
- 旧 DELETE 撤回接口仍兼容，会使用默认撤回原因并通知报名者。
- 活动编辑和取消，与给当时已报名账号的通知写入处于同一个事务中。未报名者不会收到消息。
- GET /api/notifications 返回当前账号最近 200 条通知；POST /api/notifications/:id/read 标为已读，POST /api/notifications/read-all 全部已读。不能读写他人通知。
- 截止提醒在登录后查询通知时生成：已报名且尚未取消的活动，距可识别截止时间 24 小时内提醒一次，相同截止时间不会重复生成。不猜测未知日期，不包含短信、邮件或离线推送。
- 导航未读数和通知页每 30 秒查询一次，消息和已读状态保存在 SQLite，重启保留。离线期间若整个提醒窗口已过，不补发截止提醒。
- 搜索支持关键词、类型、活动开始日期区间、剩余名额和未设上限筛选；日期含首尾当天、无年份按北京时间今年解释，无法识别日期在日期筛选时排除。未知名额不视为未设上限；有名额不代表未截止。
- server/data/events.sqlite 自动无损增加字段及通知表，不删除已有数据。测试使用独立数据库；Node.js 24 运行 npm test 可验证权限、持久化、取消、CSV 和筛选。

报名：GET /api/events/:id/registration 读取实时名额及当前用户报名状态；POST 同路径报名，DELETE 同路径取消报名。
GET /api/registrations 返回当前账号的报名记录，包括已撤回活动。
报名和取消须登录；每个账号每场活动只占一个名额，取消后释放。SQLite BEGIN IMMEDIATE 事务内检查名额并写入，避免超额。
撤回活动禁止新增报名，已有记录保留并显示撤回状态；允许取消。人数上限未注明时不执行名额限制。

收藏/加入我的活动不等于报名，仅后端发布的活动支持真实报名。账号与报名数据均保存在 SQLite。

注册登录：POST /api/auth/register、POST /api/auth/login，JSON 为 studentId、password。
学号为 6–20 位数字，独立密码为 8–128 个字符（最多 256 UTF-8 字节）。不核验学校身份，勿使用学校门户密码。
GET /api/auth/me 恢复登录状态，POST /api/auth/logout 退出并撤销会话。

旧活动会保留，但没有管理凭证，不能自动认领。

# CCNU Radar · 华中师范大学校园活动雷达

**让校园活动，不再错过。** 面向校园活动发现、通知解析、报名和组织管理的全栈黑客松项目。

学生可以搜索活动、阅读通知摘要、报名、查询名额和加入活动 QQ 群；发布者可以发布及编辑活动、查看和导出名单、取消活动并发送站内通知。

## 功能

| 使用场景 | 已实现功能 |
| --- | --- |
| 发现活动 | 近期真实活动、关键词搜索、类型 / 日期 / 剩余名额筛选、演示活动明确标识 |
| 理解通知 | 无 Key 可用的模拟解析；可选 DeepSeek；摘要、参与建议、截止提醒；缺失信息不编造 |
| 参与活动 | 学号＋独立密码、报名及取消、事务保护名额、个人报名记录、活动详情和可复制 QQ 群号 |
| 管理活动 | 发布、编辑、取消原因、仅发布者可见的名单和 CSV 导出 |
| 消息与体验 | 站内通知、首次注册教程、收藏记录、玻璃风格界面、移动端布局、前进 / 后退 / 刷新 |

## 快速启动

需要 **Node.js 24**（自带 npm）。Windows、macOS、Linux 均可按下面的命令运行。进入下载或克隆得到的项目根目录：

```sh
npm run setup
npm run build
npm start
```

打开 **http://localhost:3001**。该窗口同时运行网页和后端，保持窗口开启，按 Ctrl+C 停止。首次访问数据库为空，在网页注册自己的演示账号、发布活动即可。**无需 DeepSeek Key 即可使用模拟解析和全部报名管理功能。**

Windows 也可双击根目录 `start-local.cmd`，它会检查依赖、构建并启动。若提示端口被占用，停止之前的后端后再启动，不需要删除任何数据库。

### 继续开发

需要热更新时，在两个终端分别运行：

```sh
npm run dev:server
```

```sh
npm run dev
```

访问 http://localhost:5173。Vite 将 `/api` 代理到 3001。`npm start` 的单窗口模式和开发后端不能同时占用 3001；已有单窗口服务时，可仅额外启动 Vite。

### 可选：真实 AI

复制 `server/.env.example` 为 `server/.env`，在本机填写 `DEEPSEEK_API_KEY`，按账号可用模型设置 `DEEPSEEK_MODEL`，然后重启服务。不要把 Key 放入前端变量，也不要提交 `.env`。真实解析需要先登录；模拟解析不向外发送通知文本。

```dotenv
DEEPSEEK_API_KEY=
PORT=3001
DEEPSEEK_MODEL=deepseek-flash
```

`npm start` 读取 PORT；开发代理固定指向 3001，开发时改变 PORT 需同步修改 `vite.config.ts`。本地启动器使用 HTTP；不设置 `NODE_ENV=production`。公网临时分享入口使用 HTTPS 和 Secure Cookie。

## 五分钟演示

1. 注册发布者账号，完成或跳过新手教程。学号为 6–20 位数字，独立密码至少 8 个字符。
2. 在“发布活动”填写一个未来日期的活动，人数上限设为 1，选填 QQ 群号。
3. 使用另一个浏览器或无痕窗口注册参与者账号，在搜索页找到活动，查看详情并报名。剩余名额变为 0，再次报名不会重复占位。
4. 发布者在“我的发布”查看和导出名单，编辑地点或群号；参与者在站内通知看到变更。
5. 参与者取消报名，名额释放；发布者可填写原因取消活动，参与者仍能查看取消记录。
6. 在“AI 智能解析”选择示例，点击“使用模拟解析”，查看摘要和提醒；收藏后在“我的活动”中查看，刷新后仍保留。

详见 [演示与验收清单](docs/ACCEPTANCE.md)。请使用虚构测试账号和活动，不上传真实学生名单。

## 检查与测试

```sh
npm run check
```

依次执行 ESLint、自动测试、TypeScript 和 Vite 构建。测试使用独立内存或临时数据库，覆盖身份与权限、报名竞争、名额释放、编辑取消、名单导出、通知、群号、教程、页面导航与活动状态。无需真实 API Key，不调用付费 AI。GitHub Actions 使用 Node.js 24 重复执行同一检查。

## 结构与数据

```text
src/
  components/     活动卡片、表单、详情、导航和教程
  pages/          首页、搜索、解析、登录、发布和通知页面
  services/       API 客户端、模拟解析、收藏存储
  types/          TypeScript 数据结构
  utils/          活动状态、日期、筛选、导航
server/
  index.js        Express API 和鉴权
  serve.js        同源网页＋API 单窗口入口
  auth.js         scrypt 密码哈希、会话
  events.js       SQLite 活动数据
  registrations.js / activity-management.js  报名和发布管理
  *.test.js       独立自动测试
docs/             交付和验收说明
```

账号、活动、报名和通知保存在 `server/data/` 的 SQLite 数据库，重启仍保留；数据库不在仓库中。备份时先停止所有后端和分享进程，再复制整个 `server/data/` 到私有备份位置。个人收藏保存在当前浏览器 localStorage，尚不跨设备同步。

## 临时公网演示

已配置 ngrok 的本机可运行 `npm --prefix server run share:ngrok`；代码更新后先重新构建，再重启分享。首次配置参见 [后端说明](server/README.md)。分享会启动独立的 3002 服务，与本地后端共用数据库。`server/tools/ngrok.exe` 和本机令牌不随仓库分发，需要自行安装配置。

公网链接是运行时生成的临时入口，需保持电脑联网、服务运行；GitHub 仓库只保存源码，**不会自动托管 Express / SQLite 后端**。不要把 GitHub Pages 当作全栈运行入口。

## 当前边界

- 黑客松可运行版本，非学校官方系统；学号由用户填写，尚无学校身份核验、密码找回、发布审核。
- 站内通知需打开网页查询，每 30 秒刷新，不包含短信、邮件或离线推送。
- 入群、收藏和报名是不同操作；QQ 群号由发布者提供，加入须遵循群设置。
- 真实 AI 依赖外部账户、余额和网络；有超时、登录限制、演示调用额度与模拟备用入口。
- SQLite 适用于当前单机演示。面向正式长期运营还需部署、运维备份、身份与内容治理。

后端接口及安全设计详见 [server/README.md](server/README.md)。

# CCNU Radar 演示与验收

## 环境

- Node.js 24；仓库全新副本运行 `npm run setup`、`npm run check`、`npm start`。
- 浏览器打开 http://localhost:3001，健康接口 `/api/health` 返回 status=ok。
- 不需要提供 API Key；模拟解析可直接演示。

## 双账号闭环

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 注册 | 两个不同浏览器分别注册发布者与参与者 | 会话独立；教程可完成，刷新后不重复自动弹出 |
| 发布 | 填写未来日期、地点、人数上限 1、QQ 群号 | 首页和搜索展示已发布活动 |
| 报名 | 参与者在详情报名 | 已报 1 人、剩余 0；重复提交不占新名额 |
| 管理 | 发布者查看 / 导出名单 | 只有发布者能查看学号；CSV 中文可读 |
| 修改 | 发布者编辑地点、群号 | 原报名保留；参与者收到站内通知 |
| 释放名额 | 参与者取消报名 | 名额恢复，可重新报名 |
| 取消活动 | 发布者填写取消原因 | 停止公开展示和新增报名；保留历史报名、原因及通知 |
| 收藏 | 模拟解析后收藏，进入我的活动并刷新 | 内容持久保存在当前浏览器 |
| 导航 | 页面切换、刷新、浏览器后退 | 地址与页面一致，切换页面回到顶部 |

## 展示建议

先讲“通知分散、活动容易错过”的问题，再演示“发现→理解→报名→发布管理→消息通知”。展示 AI 解析时明确模拟或真实来源。活动日期使用演示当天之后的绝对日期，避免测试样例已截止影响报名。

## 提交检查

- 仓库 README 包含安装、启动、演示与已知边界。
- `npm run check` 通过，GitHub Actions 结果可查看。
- 仓库不含 `.env`、ngrok 令牌、真实 SQLite 数据库、用户名单、node_modules。
- GitHub 仓库链接与临时演示链接分别提交；临时链接需要本机服务持续在线。
- 真实 AI 需要自行配置凭证，自动测试不代表已验证外部供应商在线可用性。
